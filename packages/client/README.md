# @celiador/client — the daemon's client contract

One description of the daemon's HTTP API, shared by every client:

| File | What it is |
|---|---|
| [`openapi.yaml`](openapi.yaml) | OpenAPI 3.1 spec of every route in `daemon/src` — request bodies, responses, errors, auth, and the event payloads of the SSE streams. **The source of truth.** |
| [`src/schema.ts`](src/schema.ts) | TypeScript types generated from it with [openapi-typescript](https://openapi-ts.dev) (pinned). Committed; never edit by hand. |
| [`swift/CeliadorAPI.swift`](swift/CeliadorAPI.swift) | Swift `Codable` types for `components.schemas`, generated by [`scripts/generate-swift.mjs`](scripts/generate-swift.mjs). Committed; never edit by hand. |
| [`routes-allowlist.txt`](routes-allowlist.txt) | Daemon routes deliberately left out of the spec (empty today). |
| [`scripts/breaking-since.sh`](scripts/breaking-since.sh) | Breaking changes since a git ref, with a pinned oasdiff. |

Clients: the editor's built-in `celiador-ai` extension (`Cliefden/celiador-editor`),
`celiador-remote` (`Cliefden/celiador-remote`) and the iOS app (`ios/`). The two
extensions vendor `src/schema.ts` at a pinned commit of this repository (their
`scripts/sync-contract.mjs`), which is why it stays **committed** here rather
than generated at build time: they fetch it from GitHub by commit.

## The rule: API changes are additive only

Released clients can't be updated in lockstep with the daemon. An editor build
from months ago, a `celiador-remote` version someone never updated, and an iOS
build waiting in App Review all talk to the same production daemon. So:

- **Never remove or rename** a route, a field, a query parameter, an enum value
  the daemon sends, or an SSE event kind.
- **Never make an optional field required**, in a request or a response.
- **Never change a field's type** (or narrow it: `string | null` stays nullable).
- **New request fields are optional**, with the old behaviour when absent.
- **New response fields are optional** in the spec, so old clients that don't
  know them keep decoding.
- **New enum values and event kinds are allowed**, and clients must ignore the
  ones they don't know (the iOS decoders included).
- To retire something, stop using it in every client first; mark it
  `deprecated: true` in the spec and keep serving it until no released client
  sends it.

What is enforced (`.github/workflows/client-contract.yml`):

- **The spec covers the daemon.** `npm run check:api-coverage` in `daemon/`
  builds the real app and compares its `/api` routes with `openapi.yaml`: a
  route served but not documented, or documented but not served, fails (path
  parameters are compared by position, so `:rid` matches `{requestId}`). A
  route that is genuinely not for clients goes in `routes-allowlist.txt` with a
  reason; a stale entry fails too.
- **No accidental breaks.** On every pull request,
  [oasdiff](https://github.com/oasdiff/oasdiff) compares `openapi.yaml` with the
  base branch's and fails on a breaking change. A deliberate break passes with
  the `api-breaking` label.
- **A break costs a MINOR release.** `scripts/release.sh` compares the spec with
  the last release tag and refuses a PATCH bump when anything broke (below 1.0;
  a MAJOR one from 1.0). A `vX.Y.Z` tag pushed without the script is checked
  against the previous tag the same way. The release's changelog says what
  clients have to do.

The spec still describes response shapes by hand; nothing checks a handler's
actual JSON against it yet (a candidate: validate the smoke test's responses).

## Changing the API

The spec is maintained by hand next to the handlers. In the same pull request
that changes a route in `daemon/src`:

1. Update `openapi.yaml` (route, request/response schema, status codes).
2. Regenerate the types and commit them:

   ```sh
   cd packages/client
   npm ci
   npm run generate   # openapi.yaml → src/schema.ts + swift/CeliadorAPI.swift
   npm run check      # what CI runs: regenerate + fail on diff, then tsc
   npm run test:swift # swiftc typecheck (Swift 5 + 6) + the decode test
   ```

3. Check coverage and breaks locally:

   ```sh
   (cd daemon && npm run check:api-coverage)
   packages/client/scripts/breaking-since.sh origin/main   # or a release tag
   ```

## Using the types (TypeScript)

```ts
import type { components, paths } from "@celiador/client"; // or a relative path to src/schema.ts

type Session = components["schemas"]["Session"];
type SessionEvent = components["schemas"]["SessionEvent"]; // the SSE payload of GET /api/sessions/{id}/events
type TaskList = paths["/api/tasks"]["get"]["responses"][200]["content"]["application/json"];
```

The types have no runtime part. They also work with
[openapi-fetch](https://openapi-ts.dev/openapi-fetch/) should a client want a
typed fetch wrapper, but nothing requires it.

### Server-Sent Events

OpenAPI 3.1 has no way to type an SSE stream's events, so each `text/event-stream`
response lists its events in an `x-sse-events` extension (event name → schema;
`message` is the unnamed default event) and the payload schemas live in
`components.schemas`:

| Stream | Event payloads |
|---|---|
| `GET /api/sessions/{id}/events` | `SessionEvent` (frame `id` = `seq`) |
| `GET /api/sessions/{id}/commands` | `SessionCommand` |
| `GET /api/presence/commands` | `EditorCommand` |
| `GET /api/tasks/stream` | `Task` (event name `task`) |
| `POST /api/agent/messages` | `AnthropicStreamEvent`, `AgentStreamError` |
| `POST /api/anthropic/v1/messages` (`stream: true`) | Anthropic's stream, passed through |

Every stream also sends an empty `ping` event as a heartbeat.

## Swift

[`swift/CeliadorAPI.swift`](swift/CeliadorAPI.swift) is one file of plain
`Codable`, `Sendable`, `Equatable` types for every schema in
`components.schemas` — no client, no paths, no `import` at all (not even
Foundation). The iOS app's API code (`ios/Shared/`) has to stay
dependency-free because it compiles into the app, the widgets and the Live
Activity, and Apple's
[swift-openapi-generator](https://github.com/apple/swift-openapi-generator)
imports `OpenAPIRuntime` even in types-only mode, so the file comes from a
small generator of our own: [`scripts/generate-swift.mjs`](scripts/generate-swift.mjs)
(Node, the pinned `yaml` parser, nothing else). `npm run generate` writes it,
`npm run check` fails when it's stale, and CI typechecks it with `swiftc` in
Swift 5 and 6 modes (warnings as errors) and runs a decode test
([`test/swift/DecodeTest.swift`](test/swift/DecodeTest.swift)) via
`npm run test:swift` (on a Mac: `DEVELOPER_DIR=… npm run test:swift`).

Everything lives in a `CeliadorAPI` namespace (`CeliadorAPI.Session`,
`CeliadorAPI.SessionEvent`, ...), so names like `Task` and `Error` never shadow
Swift's own, nor the app's hand-written models.

| Spec | Swift |
|---|---|
| object | `struct` with camelCase properties (`CodingKeys` for snake_case JSON such as `display_name`); optional when not required or nullable; a public memberwise `init` (constants and optionals defaulted) |
| object with `additionalProperties: true` and named properties | the same, plus `additionalProperties: [String: JSONValue]` holding the rest (decoded and re-encoded) |
| object with only `additionalProperties` | `[String: T]`, or `[String: JSONValue]` when free-form |
| `allOf` | one flattened struct (inline types of a referenced part are reused, e.g. `SessionEventMessage.role` is a `RunnerEventMessage.Role`) |
| string `enum` | a `RawRepresentable` struct with a constant per value (`TaskState.prOpen`), `knownValues` and `isKnown` |
| `oneOf` discriminated by `kind` | an `enum` with one case per kind (`.toolResult`, `.fsList`, `.startRun`) plus `.unknown(kind:payload:)` |
| other `oneOf` | an `enum` (`.string`, `.array`, `.waitlistName`, ...); decoding tries the variants in order |
| `{}` (any value) | `JSONValue` |
| integer / number / boolean / string | `Int` / `Double` / `Bool` / `String` — `date-time`, `date`, `uri`, `uuid` stay `String` (parse where you need a `Date`; the daemon's timestamps carry milliseconds, which `.iso8601` rejects) |

### Unknown values: decode, don't fail

The API only grows (see the rule above), so a released app will meet enum
values and event kinds it was built without. The generated types never throw
on them:

- **Enum values** decode into the `RawRepresentable` struct whatever the string;
  `switch` over the constants needs a `default:` branch, and `isKnown` says
  whether this build knows the value. (A Swift `enum` would throw on a new value
  and break decoding of the whole response.)
- **Event and command kinds** this build doesn't know decode to
  `.unknown(kind:payload:)` with the whole payload as `JSONValue` (the event's
  `seq` included), so a stream reader can skip them and still advance.
- **Unknown fields** are ignored (or, on open objects, kept in
  `additionalProperties`).

A known kind with a malformed body still throws: that's a daemon bug, not a
new version.

### Using it from the iOS app (proposal, not done yet)

The app doesn't use these types yet; its hand-written models in `ios/Shared/`
stay until they're switched over one at a time. The proposed wiring is an
XcodeGen source path, so the generated file compiles into the same targets as
`Shared/` and nothing is copied:

```yaml
# ios/project.yml, in each target that compiles the API code (app, widgets)
sources:
  - path: ../packages/client/swift
    group: Shared/Generated
```

Then replace a hand-written model with a typealias (`typealias Session =
CeliadorAPI.Session`) or use the namespaced type directly, screen by screen,
with the decode tests in `ios/` covering the switch. Because the file has no
imports and is Swift 6 clean, the widget and Live Activity targets can take it
as is.
